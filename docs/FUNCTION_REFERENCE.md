# Function reference for manual code review

This is a source-level catalogue of the application's authored functions, including private helpers, signals, inline getters, callback contracts, QML handlers, and build entry points. [TEST_FUNCTION_REFERENCE.md](./TEST_FUNCTION_REFERENCE.md) covers test cases, mocks, and test helpers. Read it alongside [ADR 0009](./adr/0009-exclusive-source-lifecycle.md), [SYSTEM_INTERFACE.md](../SYSTEM_INTERFACE.md), and the [manual acceptance plan](../MANUAL_TEST_PLAN.md).

## Reading conventions

Inline C++ declaration comments use `///` with parameter/return contracts; QML handlers and build/script entry points use adjacent comments. Private methods are documented at their header declarations, with implementation-local helpers and asynchronous capture/result notes beside their definitions/callbacks. Keep these comments and the catalogue aligned when behavior changes.

- **None** in the parameter column means the function takes no explicit arguments. Cached member state and captured lambda variables are dependencies, not parameters.
- **`void`** means no returned value. It does not indicate success. Async outcomes arrive through callbacks, properties, or signals; a method/job acknowledgement is not proof of observed readiness.
- Constructors/destructors have **no return value/type**. A default `parent=nullptr` is the optional QObject owner. Injected D-Bus connections are copied handles; injected network managers remain caller-owned unless the default constructor explicitly parents its newly created manager.
- Returned child QObject pointers are **borrowed**, owned by the controller. Do not delete them. Getter results are snapshots of cached state, not fresh external queries.
- Playback positions/durations are **milliseconds** unless explicitly stated otherwise. MPRIS wire times are microseconds; Bluetooth wire times are milliseconds. Percentages are integer percentages, not 0–1 ratios.
- Qt signals below return `void`; their implementation is generated by moc. Framework-generated metaobject methods, implicitly generated C++ special members, standard/library functions, and generated QML-cache code are not separately authored functions.
- Inline QML event handlers are included even when written as `onClicked: expression` rather than a named JavaScript function. Their return is normally JavaScript `undefined` and is not consumed by Qt.
- This documents **current behavior**, including guards and limitations; it is not a claim that physical Pi acceptance has passed.

Suggested review order: startup → facade transition ordering → service/adapter observation → pairing/takeover → transport/metadata → Wi-Fi/volume/power → QML → test boundary fidelity.

## Review checkpoints

1. Follow `beginTransition → advanceTransition → requestRunning/requestAdapterPowered → fresh observation`. Check all failure paths freeze commands, preserve selection, and guard stale generations.
2. Read cached getter predicates exactly: `running()`, `sinkReady()`, and `isAvailable()` are not interchangeable with sourceReady/known state.
3. For every async callback, check capture lifetime, watcher/process ownership, timeout, token validation, and recovery/error-clearing behavior.
4. Review pairing sender validation, delayed replies, stale decisions, unsupported association flows, and teardown; service authorization currently uses Paired without a UUID allowlist.
5. Inspect cache/metadata semantics: URL versus caller key, missing fields, rate-limited request starts, old replies warming cache, and empty-result meanings.
6. Compare mocks to actual D-Bus signatures and observed completion, using the test catalogue. Physical verification outcomes belong in the acceptance plan, not inferred from a `void` call or passing mock.
